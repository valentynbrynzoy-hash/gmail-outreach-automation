# 📬 Gmail Outreach Automation — Google Apps Script

Система email-аутрича для работы с блогерами на Google Apps Script + Google Sheets.

Закрывает полный цикл: холодное письмо → фолоу-апы в треде → детектирование ответов → обработка bounces — всё по местному времени блогера с умной рандомизацией слотов.

---

## Что умеет

- **Плановая рассылка** — отправляет в местное время блогера, конвертируя из его гео-таймзоны в UTC
- **Фолоу-апы в треде** — отвечает внутри оригинального треда через Gmail API с корректными заголовками `In-Reply-To`
- **Умный рандомайзер** — распределяет фолоу-апы в окне ±45 мин, минимальный зазор между слотами 3 мин
- **Детектирование ответов** — трёхпроходный поиск: по треду, по теме письма, по домену отправителя
- **Обработка bounces** — парсит заголовки mailer-daemon / postmaster, помечает строки автоматически
- **Ротация шаблонов** — отслеживает использованные ID по каждому аккаунту, не повторяет в заданном окне
- **Мультиаккаунт** — один `Code.gs` на каждый Gmail; все аккаунты работают с одной таблицей
- **Батч-обработка** — постоянный курсор батча на аккаунт, не выбивает лимиты Gmail API
- **Авточистка лога** — еженедельный крон удаляет записи старше N дней
- **Статус-дашборд** — ячейка статуса триггера для каждого аккаунта на листе Меню

---

## Скрипты

| Файл | Назначение |
|------|-----------|
| `Code.gs` | Основной скрипт — рассылка, фолоу-апы, проверка ответов, bounces. **Один экземпляр на каждый Gmail-аккаунт** |
| `BatchFiller.gs` | Вспомогательный скрипт — автозаполнение даты, аккаунта и времени отправки по новым строкам. Привязывается к таблице |

---

## Архитектура

```
Google Sheet (общая для всех аккаунтов)
├── 📋 Меню          — дашборд, список аккаунтов, настройки параметров
├── 📮 Почты         — строки блогеров (одна строка = один блогер)
├── 📧 Шаблоны       — профили отправителей + шаблоны холодных писем
├── 🔁 Фолоу-апы     — шаблоны фолоу-апов (по номеру ФА + стилю)
└── 📊 Логи          — лог отправок / проверок / bounces
```

**Каждый Gmail-аккаунт = отдельный Apps Script проект**, но все они работают с одной таблицей. Единственное отличие между копиями скрипта — значение константы `MY_ACCOUNT`.

## Установка

### Шаг 1. Скопируй таблицу

Открой [шаблон таблицы](https://docs.google.com/spreadsheets/d/16qKjhrJZzfqZ-qPVH3sqlcZZYcB5ilYC4bQ80HpGmqk/edit?usp=sharing) → **Файл → Создать копию**. Запомни `SPREADSHEET_ID` из URL своей копии:
```
https://docs.google.com/spreadsheets/d/SPREADSHEET_ID/edit
```

> ⚠️ **Важно:** дай доступ к таблице для каждого Gmail-аккаунта, который будет отправлять письма. Кнопка **«Поделиться»** → добавь email с правами **«Редактор»**. Без этого скрипт не сможет читать и писать данные под чужим аккаунтом.

### Шаг 2. Подключи BatchFiller (через таблицу)

Открой таблицу под основным аккаунтом → **Расширения → Apps Script** → вставь содержимое `BatchFiller.gs` → сохрани. После обновления страницы появится меню **📬 Рассылка**.

### Шаг 3. Создай проект для каждого Gmail-аккаунта

> **Один Gmail-аккаунт = один Apps Script проект.** Скрипт отправляет письма от имени того аккаунта, под которым открыт проект, поэтому смешивать нельзя.

Для каждого аккаунта:

1. **Войди в Google** под нужным Gmail-аккаунтом
2. Открой [script.google.com](https://script.google.com) → **Новый проект**
3. Вставь содержимое `Code.gs`
4. Измени константы в верхнем блоке:

```javascript
const SPREADSHEET_ID = 'ID_ТВОЕЙ_ТАБЛИЦЫ';       // из URL таблицы
const MY_ACCOUNT     = 'этот_аккаунт@gmail.com';  // Gmail этого проекта

const ACCOUNT_ROW = {
  'первый@gmail.com':  6,   // номер строки в листе 📋 Меню
  'второй@gmail.com':  7,
};
```

5. Сохрани проект
6. Включи Gmail API: **Сервисы → Добавить → Gmail API**
7. Запусти `createTriggers()` один раз

### Шаг 4. 🔐 Авторизация скрипта

При первом запуске (`createTriggers` или любой функции) Google попросит разрешения.

1. Появится окно **«Требуется авторизация»** → нажми **Продолжить**
2. Выбери тот же Gmail-аккаунт, что указан в `MY_ACCOUNT`
3. Увидишь предупреждение **«Google не проверил это приложение»** — это нормально для личных скриптов
4. Нажми **«Дополнительные настройки»** → **«Перейти на страницу [название проекта] (небезопасно)»**
5. Нажми **Разрешить**

> ⚠️ Если авторизоваться под другим аккаунтом — письма будут уходить не с того адреса. Всегда проверяй, что аккаунт в окне авторизации совпадает с `MY_ACCOUNT`.

### Шаг 5. Заполни таблицу

- **📧 Шаблоны** → строка профиля отправителя для каждого `MY_ACCOUNT` (отметь активным `✅`)
- **📧 Шаблоны** → хотя бы один активный шаблон письма
- **🔁 Фолоу-апы** → шаблоны для ФА №1, №2, №3
- **📮 Почты** → строки блогеров: имя, гео, дата, местное время, email, аккаунт, стиль шаблона

## Параметры

В **📋 Меню**, строки 19–32, пары ключ-значение:

| Ключ | По умолчанию | Описание |
|------|-------------|----------|
| `FOLLOWUP_ENABLED` | `TRUE` | Включить/выключить фолоу-апы |
| `FOLLOWUP_COUNT` | `3` | Максимум фолоу-апов на блогера |
| `FOLLOWUP_INTERVAL_1` | `1` | Дней после холодного письма до ФА1 |
| `FOLLOWUP_INTERVAL_2` | `5` | Дней после ФА1 до ФА2 |
| `FOLLOWUP_INTERVAL_3` | `7` | Дней после ФА2 до ФА3 |
| `CHECK_REPLIES_ENABLED` | `TRUE` | Включить проверку ответов |
| `CHECK_REPLIES_DAYS` | `30` | Сколько дней назад проверять |
| `CHECK_BATCH_SIZE` | `150` | Строк за один запуск проверки |
| `DAYS_UNIQUE` | `5` | Дней до повторного использования холодного шаблона |
| `DAYS_UNIQUE_FOLLOWUP` | `5` | Дней до повторного использования шаблона ФА |
| `BOUNCE_CHECK_ENABLED` | `TRUE` | Включить bounce-детектор |
| `LOG_RETENTION_DAYS` | `30` | Сколько дней хранить лог |
| `FOLLOWUP_STOP_ON_REPLY` | `TRUE` | Остановить цепочку ФА при получении ответа |

## Статусы

### Режимы строк

| Режим | Поведение |
|-------|-----------|
| `полный` | Отправка + фолоу-апы + проверка ответов |
| `только проверка` | Без отправки, только проверка ответов |
| *(пусто)* | Устанавливается в `полный` автоматически после первой отправки |

### Статусы фолоу-апов

| Статус | Значение |
|--------|----------|
| `ожидание` | ФА запланирован, ждёт времени отправки |
| `ответил` | Получен ответ, цепочка остановлена |
| `завершён` | Все ФА отправлены |
| `нет треда` | Оригинальный тред не найден в Отправленных |
| `bounce` | Письмо вернулось, остановлено |

## Триггеры

Создаются через `createTriggers()`:

| Функция | Расписание |
|---------|-----------|
| `sendScheduledEmails` | Каждую минуту |
| `sendFollowUps` | Каждую минуту |
| `checkReplies` | Каждые 3 часа |
| `checkBounces` | Каждые 6 часов |
| `updateTriggerStatus` | Каждые 5 минут |
| `cleanLog` | Воскресенье в 3:00 |

## Поддерживаемые ГЕО

Конвертация местного времени в UTC по захардкоженным смещениям:

`ПЕРУ` (-5), `ЧИЛИ` (-3), `АРГЕНТИНА` (-3), `КОЛУМБИЯ` (-5), `МЕКСИКА` (-6), `БРАЗИЛИЯ` (-3), `УКРАИНА` (+3), `ТАИЛАНД` (+7), `МОНГОЛИЯ` (+8), `ПАКИСТАН` (+5), `ШРИ-ЛАНКА` (+5)

Добавить новое ГЕО — расширить объект `GEO_OFFSETS` в начале `Code.gs`.

## BatchFiller — автозаполнение новых строк

| Константа | По умолчанию | Описание |
|-----------|-------------|----------|
| `BF_INTERVAL_MIN` | `5` | Минут между письмами одного аккаунта |
| `BF_START_TIME` | `09:00` | Время старта (украинское) |
| `BF_MAX_PER_ACC` | `10` | Максимум писем на аккаунт в день |

**Что делает:**
- Находит строки в 📮 Почты, где есть имя и гео, но не заполнены аккаунт и дата
- Распределяет по активным аккаунтам равномерно (до `BF_MAX_PER_ACC` на аккаунт в день)
- Проставляет дату отправки, аккаунт и местное время с шагом `BF_INTERVAL_MIN`
- Умеет пропускать выходные

## Служебные функции

| Функция | Что делает |
|---------|-----------|
| `createTriggers()` | Создаёт все триггеры (один раз при настройке) |
| `deleteTriggers()` | Удаляет все триггеры |
| `resetStatus()` | Сбрасывает статус отправки по всем строкам |
| `cleanLog()` | Запускает очистку лога вручную |

## Технические детали

- Runtime: Google Apps Script (V8)
- Зависимости: Gmail API (включить вручную через Сервисы)
- ES5-совместимый JavaScript
- Лимит Gmail API: до 200 поисковых вызовов за запуск (`GMAIL_CALL_LIMIT`)
